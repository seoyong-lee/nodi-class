<h2 id="part-00">Part 00. 먼저 알아두기</h2>

### PPT 잘 만드는 사람은 PPT부터 만들지 않습니다

예전에는 AI로 PPT를 만들면 페이지마다 폰트와 여백이 제각각이거나, 차트가 이미지처럼 만들어져 숫자 하나만 바꿔도 다시 만들어야 하는 경우가 많았어요. 그런데 지금은 기준을 먼저 잡고 수정 가능한 형태로 요청하면 실무에서 계속 다듬어 쓸 수 있는 수준까지 만들 수 있습니다.

### 어떤 Claude를 써야 할까?

| 방법 | 이런 사람에게 추천 |
|---|---|
| 일반 Claude | 채팅에서 자료를 넣고 PPT 파일까지 바로 만들고 싶은 사람 |
| Claude Design | 디자인을 직접 보면서 만들고 다듬는 과정이 중요한 사람 |
| Claude for PowerPoint | 기존 회사 PPT를 PowerPoint 안에서 직접 열어 수정하고 싶은 사람 |

<Callout tone="tip">
이 가이드북은 별도 프로그램 설치 없이 누구나 바로 따라 할 수 있도록, 일반 Claude의 파일 생성 기능을 기준으로 설명합니다. 여기서 만드는 디자인 시스템과 프롬프트는 Claude Design·Claude for PowerPoint를 쓸 때도 그대로 참고할 수 있어요.
</Callout>

### 다섯 단계로 완성합니다

이 가이드북은 프롬프트 몇 개를 던져주는 자료가 아니라, PPT를 대하는 사고방식을 다섯 단계로 정리한 자료예요. 순서대로 따라오시면 됩니다.

1. 좋은 기준을 찾는다 — 목적에 맞는 레퍼런스를 고른다.
2. 기준을 언어화한다 — 레퍼런스를 반복 가능한 디자인 시스템으로 정리한다.
3. 한 장으로 검증한다 — 전체를 만들기 전에 한 장으로 기준이 맞는지 확인한다.
4. 시스템으로 저장한다 — Claude Project에 저장해서 매번 다시 설명하지 않는다.
5. 실제 업무에 적용한다 — 새 PPT 제작과 기존 자료 리디자인에 그대로 쓴다.

<Callout tone="warn">
특정 폰트를 쓰고 싶다면 이름만 알려주지 말고 폰트 파일을 함께 주세요. 폰트가 다르면 PowerPoint에서 열었을 때 글자가 밀리거나 줄바꿈이 바뀌면서 레이아웃이 통째로 틀어질 수 있어요.
</Callout>

### 이 책에서 사용하는 프롬프트

이 가이드북에서는 실제 PPT 제작 과정을 따라가며 7개의 핵심 프롬프트를 사용합니다. 처음 등장하는 Part에서 프롬프트를 직접 사용하고, 마지막 부록에서는 7개를 한곳에 모아 다시 찾을 수 있도록 정리했습니다.

STYLE → REFINE → PROJECT → MASTER → REDESIGN → DE-AI → QC

모든 프롬프트를 순서대로 사용할 필요는 없습니다.

- 처음부터 새 PPT를 만든다면 → STYLE → PROJECT → MASTER → QC
- 기존 PPT를 다시 만든다면 → REDESIGN → QC
- 디자인이 AI스럽다면 → DE-AI → QC
- 한 장을 직접 고쳤다면 → REFINE

그리고 짧은 수정 요청은 별도로 Quick Command라고 표시합니다.

<h2 id="part-01">Part 01. 좋은 레퍼런스 찾는 법</h2>

### 목적부터 정하기

레퍼런스를 고르기 전에 먼저 정해야 하는 게 있어요. "이 PPT는 무엇을 위한 자료인가"입니다. 목적에 따라 좋은 디자인의 기준 자체가 달라지거든요.

- 경영진 보고 — 숫자와 결론 중심, 정보 밀도가 높다.
- 사업계획서 — 스토리텔링과 임팩트 있는 핵심 메시지가 중요하다.
- 회사소개서 — 브랜드와 이미지 중심으로 구성한다.
- 강의자료 — 가독성이 우선이고, 한 장에 메시지 하나만 담는다.
- 제안서 — 문제 → 해결 → 근거 → 제안의 흐름을 따른다.

<Callout tone="tip">
"그래서 뭘 골라야 할까?"
이 질문에 답하려면 예쁜 디자인이 아니라, 목적에 맞는 디자인부터 찾아야 해요.
</Callout>

### 목적에 맞는 스타일 검색하기

레퍼런스를 찾을 때 "presentation design"처럼 막연하게 검색하면 아무 자료나 나와요. 목적과 스타일을 함께 넣어야 원하는 결과에 가까워집니다.

- Before → presentation design (막연한 한 단어 검색)
- After → 목적 + 스타일을 조합해서 검색

키워드 예시: annual report presentation, consulting presentation, SaaS pitch deck, minimal corporate presentation, data driven presentation, editorial presentation design

### 레퍼런스는 여기서 찾으세요

사이트 이름을 알아두면 훨씬 빠르게 시작할 수 있어요. 아래 네 곳이면 대부분의 목적을 커버합니다.

- [Deck.gallery](https://deck.gallery/) — 실제 회사의 Pitch Deck·Investor Update·Report를 슬라이드 단위로 볼 수 있어요. "예쁜 한 장"에서 나아가 덱 전체의 흐름을 참고하기 좋습니다.
- [Pitch Presentation Gallery](https://pitch.com/presentations) — 완성도 높은 프레젠테이션을 카테고리별로 둘러볼 수 있어요.
- [Behance](https://www.behance.net/) — "presentation design"으로 검색하면 브랜딩·시각적 완성도가 높은 사례가 많이 나옵니다.
- [Slidesgo](https://slidesgo.com/) — Business, Pitch Deck, Consulting 등으로 세분화된, 실제로 편집 가능한 PPT 구조를 참고하기 좋아요.

<Callout tone="tip">
회사 양식이 없다면?
위 사이트에서 키워드를 검색해, 마음에 드는 디자인 규칙 하나를 골라 캡처한 뒤 그대로 Claude에 첨부하면 됩니다. 디자인을 따로 공부할 필요는 없어요.
</Callout>

### 좋은 레퍼런스를 고르는 5가지 기준

1. 목적이 비슷한가 — 내가 만들 자료와 용도가 같은가.
2. 위계가 명확한가 — 제목과 본문의 크기·굵기 차이가 분명한가.
3. 정보가 과하지 않은가 — 한 페이지에 너무 많은 내용을 담지 않았는가.
4. 표현이 일관성 있는가 — 차트·표·이미지를 쓰는 규칙이 페이지마다 같은가.
5. 확장이 되는가 — 10장 이상으로 늘려도 같은 스타일을 유지할 수 있는가.

### 예를 들어, 이렇게 골라봅니다

목적이 "경영진 상반기 실적 보고"라고 해볼게요. 후보 3개를 찾았다면, 앞서 본 5가지 기준으로 비교해서 하나를 고릅니다.

- 후보 A — 화려한 Pitch Deck
- 후보 B — 정보밀도 높은 Consulting Report (KPI 3개 + 막대그래프)
- 후보 C — 미니멀 Annual Report

<Callout tone="tip">
이 목적이라면 후보 B를 추천해요
경영진 실적 보고는 결론과 숫자가 먼저 보여야 해요. 후보 B는 KPI 위계가 명확하고 차트 비중이 높아 목적에 맞고, 슬라이드가 10장 이상으로 늘어나도 같은 구조를 반복하기 쉬워요. 후보 A는 인상은 강하지만 숫자가 묻히고, 후보 C는 정보 밀도가 이 목적엔 너무 낮습니다.
</Callout>

<h2 id="part-02">Part 02. 레퍼런스를 디자인 시스템으로</h2>

### 레퍼런스를 "디자인 시스템"으로 분석한다

레퍼런스를 그냥 "분석해 줘"라고 하면 Claude가 매번 다르게 분석해요. 다른 주제의 PPT를 만들어도 같은 스타일이 재현되도록, 아래 프롬프트로 항목을 명확히 지정해 주세요.

<Prompt id="style" index="01" name="STYLE" when="마음에 드는 PPT나 PDF를 찾았고, 그 스타일을 앞으로 반복해서 사용하고 싶을 때 사용합니다.">

```text
첨부한 PPT를 앞으로 제작할 발표자료의 디자인 레퍼런스로 사용하려고 해.

단순히 디자인을 설명하지 말고,
다른 주제의 PPT를 만들어도 동일한 스타일을 재현할 수 있도록
Presentation Design System 형태로 분석해 줘.

[분석 항목]

1. 전체 스타일
- 디자인을 한 문장으로 정의
- 분위기
- 정보 밀도
- 시각적 특징

2. 레이아웃
- 좌우·상하 여백
- 제목·부제목·본문의 시작 위치
- 콘텐츠 정렬 방식
- 컬럼 구조
- 같은 유형의 슬라이드에서 반복되는 기준선

3. 타이포그래피
- 제목 / 부제목 / 본문 / 캡션의 크기 관계
- 굵기
- 줄 간격
- 정렬
- 한 슬라이드의 적정 텍스트 양

4. 컬러
- Primary / Secondary / Accent / Background / Text
- 각 컬러의 HEX 값과 사용하는 조건

5. 도형과 UI 요소
- 카드 / 선 / 배지 / 숫자 강조 / 페이지 번호 / 로고

6. 이미지
- 이미지 비율 / Crop 방식 / 사진 스타일 / 이미지 배치 위치

7. 데이터 시각화
- 차트 종류 / 강조 색상 / 그리드 / 범례 / 숫자 표기 / 단위 표기

8. 반복되는 슬라이드 유형


[FIXED RULES]

새 PPT에서도 반드시 유지해야 하는 규칙을 별도로 정리해 줘.

예:
- 제목 위치
- 좌우 여백
- 기본 폰트
- 컬러 시스템
- 로고 위치
- 페이지 번호


[FLEXIBLE RULES]

콘텐츠에 따라 달라질 수 있는 규칙을 별도로 정리해 줘.

예:
- 1단 / 2단 레이아웃
- 이미지 크기
- KPI 개수
- 차트 유형
- 표 사용 여부


[TEMPLATE RULES]

다음 슬라이드 유형별 Template Rule을 만들어 줘.

- Cover
- Section
- Key Message
- KPI
- Chart
- Comparison
- Process
- Image + Text
- Table
- Closing

각 Template Rule에는:

1. 사용하는 상황
2. 제목 위치
3. 콘텐츠 영역
4. 권장 정보량
5. 강조 방식
6. 사용하면 안 되는 요소

를 포함해 줘.


[중요]

레퍼런스에 없는 디자인 요소를 임의로 추가하지 않는다.

정확히 확인할 수 없는
폰트 이름, 글자 크기, HEX 코드, 여백 값은
확정값처럼 작성하지 말고 '추정'이라고 표시한다.

타사 로고, 브랜드 컬러, 고유 일러스트와 문구는
새 PPT에 그대로 적용하지 않는다.

마지막에는 앞으로 Claude가 그대로 참고할 수 있는
PRESENTATION DESIGN SYSTEM 문서 형태로 출력해 줘.
```

</Prompt>

### 레퍼런스를 그대로 베끼지 않기

레퍼런스에서 가져올 건 "규칙"이지, 그 회사의 것 자체가 아니에요. 레퍼런스에서 구조는 가져오되, 브랜드 요소는 우리 것으로 바꿉니다.

**레퍼런스에서 가져올 것**

- 레이아웃
- 여백
- 정보 밀도
- 타이포 위계
- 차트 표현 방식
- 이미지 사용 방식

**그대로 가져오면 안 되는 것**

- 타사 로고
- 브랜드 컬러
- 고유 일러스트
- 회사 고유 그래픽
- 문구

### 예를 들면 이렇게 바뀝니다

```
REFERENCE (Blue, Helvetica, Logo A, 큰 이미지) 
→ KEEP (그리드, 여백, 타이포 위계, 이미지 비율) 
+ OVERRIDE (Orange, Pretendard, Nodi 로고, 우리 콘텐츠)
→ OUR PPT (완성된 슬라이드)
```

<Callout tone="tip">
로고 파일을 첨부했다면, 비율을 유지한 크기 조정 외에는 그대로 삽입하도록 명시하세요. 그림자·배경 박스·리컬러 같은 임의 장식이 붙으면 브랜드 가이드 위반입니다.
</Callout>

### 빈 값은 우리 것으로 채우기

레이아웃과 규칙은 레퍼런스에서 가져오고, 아래처럼 우리 값만 따로 정리해서 함께 전달하세요.

```
FONT: Pretendard
PRIMARY: #FF6B35
TEXT: #111111
BACKGROUND: #FFFFFF
LOGO: 오른쪽 하단
RATIO: 16:9
DESIGN PRINCIPLE: 한 슬라이드에 하나의 메시지만 전달한다.
```

<h2 id="part-03">Part 03. 한 장 먼저 완성하기</h2>

### 전체가 아니라 한 장만 완성한다

"좋아, 이걸로 20장 만들어 줘"라고 바로 요청하면 안 됩니다. 딱 한 장만 먼저 만들어서 기준이 맞는지부터 확인하세요.

<Prompt kind="quick" name="한 장만 먼저 만들기">

```text
방금 정한 디자인 기준으로 상반기 성과 보고서의 본문 슬라이드 한 장만 만들어 줘.
```

</Prompt>

처음 나온 결과는 분위기는 맞아도 제목 간격이 넓거나 본문이 처져 있거나 로고 위치가 어색한 경우가 많아요. 이 정도 수정은 말로 바로 요청하면 됩니다.

### Quick Commands · 눈에 띄는 부분만 수정할 때

<Prompt kind="quick" name="간격 수정">

```text
제목과 부제목 간격을 줄여 줘.
```

</Prompt>

<Prompt kind="quick" name="위치 수정">

```text
본문 전체를 조금 위로 올려 줘.
```

</Prompt>

<Prompt kind="quick" name="로고 수정">

```text
로고 위치를 오른쪽 아래로 맞춰 줘.
```

</Prompt>

### 한 장 만들고 이것부터 확인하세요

말로 수정하기 전에, 아래 여섯 가지부터 스스로 점검해보세요. QC 체크리스트예요.

1. 메시지 — 슬라이드를 3초 봤을 때 무슨 말을 하는지 알 수 있나요?
2. 정보량 — 본문을 읽지 않아도 핵심이 보이나요?
3. 정렬 — 제목·본문·차트의 기준선이 맞나요?
4. 여백 — 내용이 페이지 끝까지 꽉 차 있지 않나요?
5. 강조 — 강조 포인트가 1~2개를 넘지 않나요?
6. 반복 — 앞 슬라이드와 제목·본문 위치가 일치하나요?

### 실전 예제 — 실제로 처음부터 끝까지 해보면 이렇습니다

지금까지 배운 걸 하나의 흐름으로 이어서 보여드릴게요. "상반기 실적 보고 PPT" 본문 슬라이드 한 장을 예로 듭니다.

**입력**

- 회사 상반기 매출·KPI 데이터
- 기존 회사 PPT 한 장 (톤 참고용)
- 회사 로고

이 세 가지를 첨부하고, Part 02에서 저장한 디자인 시스템을 그대로 적용해서 만들어 달라고 요청합니다.

![](/img/resources/claude-ppt-guidebook/part03-first.png)

*첫 결과 — 카드·아이콘이 임의로 붙은 슬라이드*

- 카드마다 아이콘을 붙였지만, 정작 무엇을 뜻하는 아이콘인지 알 수 없다
- 숫자 아래 설명 문구가 또 붙어서 카드 안이 빽빽하다
- 세 숫자가 모두 같은 크기와 강조도로 표현돼 정보의 우선순위가 보이지 않는다.
- 기존 회사 PPT의 디자인 규칙에는 없던 아이콘과 카드 스타일이 임의로 반복해서 추가됐다.

### 내가 직접 수정한 기준

완벽하게 다시 그릴 필요는 없어요. PowerPoint에서 눈에 띄는 것만 직접 고칩니다. 같은 데이터를 쓰지만 강조하는 방식이 완전히 달라집니다.

![](/img/resources/claude-ppt-guidebook/part03-fixed.png)

*직접 수정한 결과 — 숫자 위계와 구분선만 남긴 슬라이드*

- 카드·아이콘을 지우고 숫자만 같은 기준선에 나란히 놓는다
- 숫자 아래 설명 문구를 지우고 한 줄짜리 라벨만 남긴다
- 카드 테두리 대신 얇은 구분선으로 영역만 나눈다
- 제목을 결론을 담은 한 문장으로 바꾼다

방금처럼 직접 고친 슬라이드가 있다면, 그 차이를 말로 설명하려 하지 말고 두 버전을 비교해 달라고 요청하세요. Claude가 내 선호를 역으로 추론해서 기준 자체를 업데이트해 줍니다.

<Prompt id="refine" index="02" name="REFINE" when="Claude가 만든 슬라이드를 내가 PowerPoint에서 직접 고쳤고, 그 수정 방향을 나머지 페이지에도 적용하고 싶을 때 씁니다.">

### Project Instructions 실제 예시

<Prompt id="project" index="03" name="PROJECT" when="한 번 만든 PPT 기준을 Claude Project에 저장해서 이후 작업에 반복 사용하고 싶을 때 사용합니다.">

```text

3. 현재 사용자의 명시적 요청
4. Approved Slides

[작업 전에]

새로운 PPT를 3장 이상 만들 때는

- 발표 목적
- 청중
- 핵심 메시지
- 전체 슬라이드 구조

정보가 부족해 결과에 큰 영향을 줄 수 있다면
```

<h2 id="part-05">Part 05. PPT 실전 Workflow</h2>

### 구조부터 설계하고 만든다

"이번 분기 마케팅 성과를 5장짜리로 만들어 줘"처럼 바로 제작시키면 시연용으로는 좋지만, 실무에서는 구조부터 잡는 편이 훨씬 안전해요.

<Prompt id="master" index="04" name="MASTER" when="디자인 시스템과 Project 세팅이 끝난 뒤, 새로운 PPT를 실제로 제작할 때 사용하는 기본 프롬프트입니다.">

```text
첨부한 자료를 바탕으로 PowerPoint 발표자료를 만들어 줘.

[목적]

PURPOSE:
{{경영진 상반기 성과 보고}}

AUDIENCE:
{{대표·임원}}

SLIDE COUNT:
{{8장 이내}}

이 Project에 저장된
Brand Guide와 Presentation Design System을
디자인 기준으로 사용한다.


[콘텐츠]

- 원문에 없는 사실·숫자·고유명사·출처를 임의로 만들지 않는다.
- 숫자와 KPI는 첨부 자료를 정확하게 유지한다.
- 한 슬라이드에는 하나의 핵심 메시지만 전달한다.
- 제목은 가능한 한 해당 페이지의 결론을 담은 문장으로 작성한다.
- 추상적인 표현보다 실제 데이터·사실·근거를 우선한다.


[시각화]

콘텐츠의 목적에 가장 적합한 표현 방식을 선택한다.

- 핵심 숫자 → KPI
- 시간에 따른 변화 → 선그래프 또는 막대그래프
- 항목 간 비교 → 막대그래프
- 구성 비율 → 도넛 또는 100% 누적 막대
- 정확한 값 조회 → 표
- 단계와 순서 → 프로세스 또는 타임라인

차트는 가능하면 PowerPoint에서
데이터와 스타일을 수정할 수 있는 형태로 만든다.


[WORKFLOW]

STEP 1.
아직 PPT 파일을 만들지 말고
먼저 전체 구조를 표로 제안한다.

각 슬라이드마다:

- 번호
- 제목
- 핵심 메시지
- 사용할 근거 / 데이터
- 표현 방식
- 이 페이지가 필요한 이유

를 작성한다.

STEP 2.
중복되거나 중요도가 낮은 페이지를 제거하고
전체 스토리라인을 다시 검토한다.

STEP 3.
내 확인을 받은 뒤
Presentation Design System을 적용해
실제 PowerPoint 파일을 제작한다.
```

</Prompt>

구조가 정리됐다면 이제 Part 02에서 저장한 디자인 시스템을 그대로 적용해서 실제 PPT를 만들면 됩니다. 내용만 다르고 스타일은 늘 같아요. 이 워크플로우는 대부분의 업무용 PPT에 그대로 응용할 수 있습니다.

- 직장인: 보고서·발표 자료
- 사업자: 회사 소개서·사업 계획서
- 강사: 강의 자료

<h2 id="part-06">Part 06. 기존 PPT·PDF 리디자인</h2>

### 유지할 것과 바꿀 것을 나눈다

예전에 만들어둔 PPT, 디자인이 오래된 자료, 다른 부서에서 받은 자료를 그대로 프로젝트에 넣고 요청하면 됩니다. 다만 "내용은 유지해줘"라고만 하면 애매하니, 아래처럼 항목을 나눠서 요청하세요.

<Prompt id="redesign" index="05" name="REDESIGN">

```text

- 제품명

[시각화]

페이지 /
현재 문제 /
유지할 내용 /
변경할 요소 /
추천 레이아웃 /
변경 이유
```

*수정 가능한 네이티브 차트 예시*

<Prompt kind="quick" name="수정 가능한 차트">

```text
실적 데이터를 참고해서 월별 성과를 한눈에 볼 수 있는 차트로 만들어 줘.

이미지로 삽입하지 말고, 
가능하면 PowerPoint에서 데이터와 스타일을 직접 수정할 수 있는 네이티브 차트 형태로 만들어 줘.
```

</Prompt>

### 차트 종류는 목적에 맞게

- 추이·시계열 데이터 → 선그래프
- 항목 간 비교 → 막대그래프
- 전체 대비 비중 → 도넛/파이. 범주가 많아지면 각도 비교가 어려우니 막대그래프나 100% 누적 막대를 고려
- 목표 대비 달성률 → KPI 카드 또는 Progress bar

### 표와 이미지도 원칙이 필요합니다

숫자는 읽는 목적에 맞게 시각화한다

- 핵심 숫자 1~3개를 강조 → 차트나 KPI 카드로
- 시간에 따른 변화를 보여줌 → 선그래프 또는 막대그래프
- 항목 간 크기를 비교 → 막대그래프
- 전체 대비 구성 비율 → 도넛 또는 100% 누적 막대
- 정확한 값을 찾아봐야 함 → 표
- 단계나 순서를 설명 → 프로세스 또는 타임라인

**표는 이럴 때만 쓴다**

- 정확한 값을 비교하거나 찾아봐야 한다면 표를 쓰고, 추세나 패턴을 보여주려면 차트를 우선한다
- 행이 많아져 한눈에 비교하기 어렵다면 핵심 행만 남기거나 시각화를 고려한다

**이미지 사용 원칙**

- 모든 이미지의 비율과 Crop 방식을 통일한다
- 장식용 이미지보다 정보 전달용 이미지를 우선한다
- 저해상도 이미지는 차라리 빼는 게 낫다

<h2 id="part-08">Part 08. AI 티 없애기</h2>

### AI 티 나는 PPT의 대표적인 특징

아래 특징이 여러 개 겹치기 시작하면, 생성형 AI 특유의 획일적인 인상이 강해집니다.

1. 모든 페이지가 카드 UI
2. 의미 없는 그라데이션
3. 필요 이상으로 둥근 도형
4. 아이콘 남발
5. 모든 문장을 3개 항목으로 정리
6. 여백이 지나치게 큼
7. 제목이 추상적임
8. 핵심 숫자가 묻힘
9. 실제 회사 자료에는 안 쓰는 장식 그래픽
10. 슬라이드마다 레이아웃이 바뀜

### 한 장으로 비교하면 이렇습니다

왼쪽은 추상적인 전략 문구를 카드와 아이콘으로 꾸민 예시이고, 오른쪽은 같은 전략을 실제 시기·과제·성공 조건으로 구체화한 예시입니다. AI 티를 줄이는 건 디자인만 덜 꾸미는 것이 아니라, 추상적인 문장을 실제 정보로 바꾸는 과정이기도 합니다.

![](/img/resources/claude-ppt-guidebook/part08-compare.png)

*한 장 비교 — 왼쪽 AI 티 나는 예시, 오른쪽 구체화한 예시*

### 이렇게 고치세요

1. 카드 UI 대신 제목·본문·여백만으로 위계를 만든다
2. 그라데이션 대신 브랜드 컬러 하나를 일관되게 쓴다
3. 도형 radius는 디자인 시스템에서 정한 값 하나만 쓴다
4. 아이콘은 정말 필요한 곳 1~2개만 남긴다
5. 항목 개수를 억지로 3개에 맞추지 않는다 — 내용이 정하도록 둔다
6. 여백은 정해둔 기준만 지킨다 — 정보 밀도는 목적에 따라 다르다
7. 제목은 결론을 그대로 문장으로 쓴다
8. 핵심 숫자는 가장 큰 글자로, 가장 먼저 보이는 자리에 둔다
9. 장식 그래픽 대신 실제 데이터·스크린샷을 쓴다
10. 같은 유형의 슬라이드는 레이아웃을 반드시 통일한다

<Callout tone="tip">
이 체크리스트만 점검해도, 생성형 AI 특유의 획일적인 디자인을 상당 부분 줄일 수 있습니다.
</Callout>

<Prompt id="deai" index="06" name="DE-AI">

```text

3. 둥근 도형을 지나치게 많이 사용하는가

9. 여백이 지나치게 많거나 정보가 과밀한가

11. 브랜드 가이드에 없는 컬러나 그래픽이 추가됐는가

각 페이지를

FIX
REDESIGN

- 왜 AI가 만든 것처럼 보이는지
- 무엇을 삭제해야 하는지
- 무엇을 강조해야 하는지
- 어떤 레이아웃으로 바꾸면 좋은지

구체적으로 제안해 줘.


마지막에는
가장 먼저 고쳐야 할 페이지 3개를 선정하고
우선순위를 설명해 줘.
```

</Prompt>
